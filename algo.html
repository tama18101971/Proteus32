2. Описание алгоритма

2.1 Принцип работы

Алгоритм реализует простой линейный wear leveling (последовательное заполнение с циклическим стиранием).

2.2 Функция flash_search_address()

Поиск свободного слота для записи и определение адреса последней валидной записи.

// Алгоритм:
// 1. Начинаем с PAGE_WRITE_START_ADDR
// 2. Проверяем первый байт слота:
//    - Если != 0xFF → слот занят, запоминаем как LastValidAddr
//    - Если == 0xFF → слот свободен, это адрес для записи
// 3. Сдвигаемся на struct_size (28 байт)
// 4. Повторяем пока не достигнем конца области
Оптимистичная проверка: Проверяется только первый байт (*(volatile uint8_t*)current != 0xFF). Это быстро, но не гарантирует валидность всей записи.

2.3 Функция read_ee()

// Алгоритм:
// 1. Ищем адрес для записи и адрес последней записи
// 2. Если last_data_address == 0 → хранилище пусто
// 3. Копируем данные во временный буфер
// 4. Считаем CRC32 всех данных (включая поле crc)
// 5. Если CRC == 0 → данные валидны, копируем в ee
// 6. Иначе → ошибка CRC

2.4 Функция write_ee()

// Алгоритм:
// 1. Вычисляем CRC32 для всех данных кроме поля crc
// 2. Записываем в поле ee.crc
// 3. Ищем свободный адрес
// 4. Если адрес == 0 (все слоты заняты):
//    a. Стираем ОБЕ страницы (128 байт)
//    b. Устанавливаем адрес на начало
// 5. Записываем структуру побайтово (Flash_ProgramWord)
// 6. Возвращаем статус успеха

2.5 Функция erase_flash()

// Алгоритм:
// 1. Разблокируем Flash
// 2. Очищаем флаги
// 3. Стираем страницу PAGE_WRITE_START_ADDR (64 байта)
// 4. Стираем страницу PAGE_WRITE_START_ADDR + 64 (64 байта)
// 5. Блокируем Flash
// 6. Возвращаем 1

4. Оценка надёжности

4.1 Сильные стороны

  • Простота: Мало кода, легко отлаживать
  • CRC32: Обнаружение ошибок в данных
  • Быстрый поиск: Проверка одного байта для определения занятости слота
  • Выравнивание: Гарантия записи целых слов (4 байта)

4.2 Слабые стороны

  • Нет атомарности: Запись может прерваться (обрыв питания)
  • Полное стирание: Стираются обе страницы даже если есть свободное место
  • Слабая валидация: Проверяется только первый байт слота
  • CRC == 0: Возможна ложная валидация (если данные дают CRC = 0)

5. Выявленные проблемы

Проблема 1: Нет атомарности записи

Серьёзность: КРИТИЧЕСКАЯ

Описание: Запись структуры из 7 слов (28 байт) выполняется побайтово в цикле. Если питание отключится во время записи, часть слов будет записана, а часть — нет. Это приведёт к:

  • Повреждению данных
  • Потере настроек
  • Возможному зацикливанию стирания
// Проблемный код:
for (uint32_t i = 0; i < struct_size / DATAWIDTH; i++) {
    FLASH_ProgramWord(ResAddress, pBuffer[i]);  // ← прерывание здесь
    ResAddress = ResAddress + DATAWIDTH;
}

Проблема 2: Полное стирание при переполнении

Серьёзность: КРИТИЧЕСКАЯ

Описание: При заполнении всех слотов стираются обе страницы (128 байт), хотя для записи новой данных нужна только одна. Это:

  • Удваивает износ Flash
  • Уменьшает срок службы в 2 раза
  • Лишняя работа (два цикла стирания)
// Проблемный код:
static int erase_flash(void) {
    FLASH_ErasePage(PAGE_WRITE_START_ADDR);        // ← лишнее
    FLASH_ErasePage(PAGE_WRITE_START_ADDR + FLASH_PAGE_SIZE);  // ← достаточно только это
}

Проблема 3: Слабая валидация слотов

Серьёзность: СРЕДНЯЯ

Описание: Проверяется только первый байт слота (*(volatile uint8_t*)current != 0xFF). Если первый байт не 0xFF, но остальные повреждены:

  • Слот считается валидным
  • Повреждённые данные будут прочитаны
  • CRC может не обнаружить проблему (если повреждение совпало с корректным CRC)

Проблема 4: CRC == 0 — ложная валидация

Серьёзность: СРЕДНЯЯ

Описание: Проверка if (sum == 0) предполагает, что если CRC32 всех данных (включая поле crc) равно 0, данные валидны. Однако:

  • Вероятность: 1/2³² ≈ 2.3×10⁻¹⁰ (крайне мала)
  • Но при повреждении данных CRC может случайно стать 0
  • Более надёжно: хранить CRC отдельно и сравнивать с вычисленным

Проблема 5: Остаточный указатель ResAddress

Серьёзность: НИЗКАЯ

Описание: Глобальная переменная ResAddress обновляется после каждой записи, но не сбрасывается при стирании. Это может привести к использованию устаревшего адреса, если стирание произошло в другой функции.

Проблема 6: Нет проверки возврата FLASH_ProgramWord

Серьёзность: НИЗКАЯ

Описание: Ошибка записи фиксируется в переменной success, но не обрабатывается. Запись продолжается даже при ошибке.

6. Рекомендации по оптимизации

Оптимизация 1: Двойной буфер (Double Buffering)

Цель: Обеспечить атомарность записи

Решение: Использовать два слота для каждой настройки. Записывать сначала в резервный, затем в основной. При чтении — брать последний валидный.

// Структура с двойным буфером
struct __attribute__((packed, aligned(4))) ee_slot {
    struct ee_data data;    // 28 байт
    uint32_t seq;           // 4 байта: номер последовательности
};

// Запись:
// 1. Увеличиваем seq
// 2. Записываем в слот 0
// 3. Записываем в слот 1 (копия)
// 4. При чтении — берём слот с наибольшим seq

Оптимизация 2: Стирание только одной страницы

Цель: Уменьшить износ Flash

Решение: Стирать только ту страницу, которая заполнена.

static int erase_flash(void) {
    // Определяем, какая страница заполнена
    uint32_t page1_start = PAGE_WRITE_START_ADDR;
    uint32_t page2_start = PAGE_WRITE_START_ADDR + FLASH_PAGE_SIZE;

    // Стираем только заполненную страницу
    if (*(volatile uint8_t*)page1_start != 0xFF) {
        FLASH_ErasePage(page1_start);
    } else if (*(volatile uint8_t*)page2_start != 0xFF) {
        FLASH_ErasePage(page2_start);
    }

    return 1;
}

Оптимизация 3: Улучшенная валидация

Цель: Обнаруживать повреждённые слоты

Решение: Проверять не только первый байт, но и CRC перед использованием.

bool is_slot_valid(uint32_t addr) {
    // Проверяем первый байт
    if (*(volatile uint8_t*)addr == 0xFF) {
        return false;
    }

    // Проверяем CRC
    struct ee_data temp;
    memcpy(&temp, (void*)addr, sizeof(struct ee_data));

    uint32_t calculated_crc = crc32_le_words(
        sizeof(struct ee_data) - DATAWIDTH, &temp
    );

    return (calculated_crc == temp.crc);
}

Оптимизация 4: Счётчик последовательности

Цель: Определять порядок записей

Решение: Добавить поле seq в структуру для отслеживания порядка.

// В структуру ee_data добавить:
uint32_t seq;  // Номер записи (увеличивается при каждой записи)

// При чтении:
// Берём запись с максимальным seq

Оптимизация 5: Проверка ошибок записи

Цель: Обрабатывать ошибки записи

Решение: Прерывать запись при ошибке и пытаться стереть.

int write_ee(void) {
    // ... существующий код ...

    for (uint32_t i = 0; i < struct_size / DATAWIDTH; i++) {
        if (FLASH_ProgramWord(ResAddress, pBuffer[i]) != FLASH_COMPLETE) {
            FLASH_Lock();
            erase_flash();
            return 0;  // Ошибка записи
        }
        ResAddress += DATAWIDTH;
    }

    FLASH_Lock();
    return 1;
}
