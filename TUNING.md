# Настройка терморегулятора (Thermal Power Limiter)

Этот документ описывает порядок практической настройки терморегулятора
(`include/thermal_limiter.h`, `src/thermal_limiter.c`) на реальном железе
по логам UART. Значения в `src/limiters.c` — сбалансированная отправная
точка; точные коэффициенты зависят от конкретного светодиода, радиатора,
термоинтерфейса и NTC-термистора.

## 1. Как читать лог

Каждые ~500 мс `main.c` печатает строку:

```
[NORMAL] T=<raw> F=<t_cur> I=<integral> L=<limiter> P=<pwm_out> S=<step_user> V=<vbat_mv>
```

| Поле | Смысл |
|------|-------|
| `T`  | Сырой код АЦП с NTC (0..1023), без фильтрации |
| `F`  | `t_cur` — отфильтрованная (EMA) температура в кодах АЦП |
| `I`  | Текущее целое значение интегратора (0..user_pwm) |
| `L`  | Текущий Limiter после slew-фильтра (сколько шагов яркости снято) |
| `P`  | Итоговый шаг яркости = `step_user - L` (что реально подаётся на светодиод) |
| `S`  | Запрошенный пользователем шаг (`step_user`) |
| `V`  | Напряжение батареи в мВ |

Одиночный сбой датчика `T` (0 или 1023 / таймаут АЦП) не гасит свет:
контроллер держит предыдущий `L`, а координатор в `limiters.c` ждёт
три подряд сбоя, и только тогда безопасно гасит фонарь (`L = step_user`).

## 2. Архитектура непрерывного PI-регулятора

Регулятор построен по схеме **непрерывного PI-контроллера с зоной удержания равновесия (Equilibrium Hold Band)**:

```
        t_threshold (T_SET - offset)              T_SET
             |                                      |
  Зона 1     |            Зона 2                    |      Зона 3
  (остывание)|    (удержание равновесия)            |    (перегрев)
  P = 0      |            P = 0                     |    P активен
  I плавно   |            delta_I = 0               |    I накапливается
  убывает    |    (интегратор удерживает мощность)  |
```

1. **Зона 3 (Перегрев, `t_cur >= T_SET`):**
   - $P = (t_{\text{cur}} - T_{\text{SET}}) \ll kp\_left\_shift$ — мгновенная пропорциональная реакция для гашения теплового всплеска.
   - Интегратор $I$ плавно накапливается: $\Delta I = (t_{\text{cur}} - T_{\text{SET}}) \gg ki\_decimation\_shift$.
2. **Зона 2 (Удержание равновесия, $T_{\text{SET}} - t_{\text{anticipate\_offset}} \le t_{\text{cur}} < T_{\text{SET}}$):**
   - $P = 0$.
   - $\Delta I = 0$: интегратор **сохраняет накопленное значение**, удерживая ту мощность, при которой тепловыделение светодиода равно рассеянию тепла корпусом. Это исключает колебания («раскачку» и циклический перезапуск турбо).
3. **Зона 1 (Остывание / восстановление, $t_{\text{cur}} < T_{\text{SET}} - t_{\text{anticipate\_offset}}$):**
   - $P = 0$.
   - Интегратор плавно уменьшается пропорционально остыванию: $\Delta I = -((t_{\text{threshold}} - t_{\text{cur}}) \gg ki\_recov\_shift)$.
   - Яркость восстанавливается мягко и предсказуемо.
4. **Суммирование $P + I$ и Slew-rate фильтр:**
   - $raw\_limiter = I + P$, ограничен $[0, user\_pwm]$.
   - `max_drop_rate` / `max_recovery_rate` ограничивают скорость изменения яркости на каждом тике (30 Гц), предотвращая любые заметные глазу мерцания.

## 3. Порядок настройки параметров

### Шаг 1. `T_SET` — целевая температура
Уставка `t_set` задаётся через инженерное/пользовательское меню (`EE.usr.t_calibr`, по умолчанию 5 = 50 °C).

### Шаг 2. `filter_shift` — фильтрация шума АЦП
По умолчанию `3` ($\tau \approx 0.27$ с на 30 Гц). Если сырой `T` в логе шумит более чем на ±3..4 кода, можно увеличить до 4.

### Шаг 3. `t_anticipate_offset` — ширина зоны удержания
По умолчанию `8` кодов (~1.0 °C). Задаёт коридор ниже $T_{\text{SET}}$, в котором интегратор зафиксирован на достигнутом уровне.
- Если на установившемся режиме температура слегка "гуляет" ниже уставки с периодическим подъёмом яркости — увеличьте `t_anticipate_offset` (на +2..4).

### Шаг 4. `kp_left_shift` — пропорциональный отклик (Зона 3)
По умолчанию `3` ($P = 8 \times \text{error}$).
- Если при резком нагреве на Turbo температура слишком сильно проскакивает выше $T_{\text{SET}}$ — увеличьте `kp_left_shift` до `4`.
- Если яркость слишком резко «проваливается» при первом же касании уставки — уменьшите до `2` ($P = 4 \times \text{error}$).

### Шаг 5. `ki_decimation_shift` — скорость набора интегратора
По умолчанию `2` ($\Delta I = \text{error} / 4$).
- Если фонарь долго держится выше уставки и медленно снижает ток — уменьшите `ki_decimation_shift` (-1: интегратор набирается быстрее).
- Если интегратор перелетает точку равновесия — увеличьте `ki_decimation_shift` (+1).

### Шаг 6. `ki_recov_shift` — скорость восстановления яркости при остывании
По умолчанию `3`.
- При остывании корпуса (ветер, рука, холодный воздух) яркость плавно нарастает до максимума.
- Если яркость восстанавливается слишком медленно — уменьшите `ki_recov_shift` (например, до 2).

### Шаг 7. `max_drop_rate` и `max_recovery_rate` — защита от мерцания
- `max_drop_rate = 3` (снижение не быстрее 90 шагов/сек).
- `max_recovery_rate = 1` (восстановление не быстрее 30 шагов/сек).
Обеспечивают абсолютно плавную для глаза регулировку без рывков и ступеней.

## 4. Шпаргалка «симптом → действие»

| Симптом | Параметр | Действие |
|---|---|---|
| Температура на Turbo сильно проскакивает $T_{\text{SET}}$ вверх | `kp_left_shift` | увеличить (+1) |
| Слишком резкий начальный спад яркости при нагреве | `kp_left_shift` | уменьшить (-1) |
| Температура на постоянном режиме держится выше $T_{\text{SET}}$ | `ki_decimation_shift` | уменьшить (-1) |
| Медленное восстановление яркости после охлаждения | `ki_recov_shift` | уменьшить (-1) |
| Периодические колебания яркости около $T_{\text{SET}}$ | `t_anticipate_offset` | увеличить (+2..4) |
| Видны ступени изменения яркости | `max_drop_rate` | уменьшить до 2 |
