# Вход в меню по напряжению (boot)

## Селекция инженерного vs пользовательского меню
`enter_menu_at_boot()` в src/ui.c (вызывается из main() сразу после ui_init, вход —
подача питания при зажатой кнопке):
```c
bool is_eng = voltage_ok && (vrefint_adc < MV_GE(ENG_VOLTAGE_MV));
...
ui_table_idx = is_eng ? ENG_MENU_IND : USR_MENU_IND;   /* 5 = eng, 6 = user */
```
- ENG_MENU_IND=5, USR_MENU_IND=6 (include/ui.h); ENG_VOLTAGE_MV=4500 mV.
- MV_GE(mv)=floor(VREF_NUMERATOR/mv)=floor(1228800/mv): 4500 мВ → код 273;
  инженерное меню при vrefint_adc <= 272 ⇔ V >= ~4.52 В.
- Физика: код Vrefint **обратно пропорционален** напряжению (mV=1228800/adc).
  Красная индикация (1 вспышка, затем 6) = eng, зелёная = user.

## Окно правдоподобия выборки АЦП (src/adc.c, adc_read)
```c
if ((vrefint_raw < 240u) || (vrefint_raw > 512u)) return false;   /* 2.4..5.1 В */
```
- 2026-08-31: верхняя граница поднята 256 → 240 (4.8 → 5.1 В), чтобы 5-вольтовый
  стенд давал валидную выборку (5.0 В → код ~245) и открывалось инженерное меню.
  До этого при 5 В adc_read() возвращал false → voltage_ok=false → vrefint_adc=0
  → меню пользователя (зелёное), а защита трактовала стенд как «критически низкое
  напряжение» (sentinel 1023−vc в adc_eff_vcode()).
- 240 = floor(1228800/5100); >5.1 В (код <240) по-прежнему отклоняется как нефизичное.
- Не снимать voltage_ok из условия селекции: сбой АЦП на загрузке оставляет
  vrefint_adc=0 → без voltage_ok меню стало бы «инженерным» (неверный fail-safe).
  Хотите ещё выше по стенду — расширяйте окно adc.c, а не условие ui.c.

## Связанное
- Калибровка voltage (vc в Option Bytes): adc.h REF_VREF_CODE=MV_GE(4200), окно ±0.29 В;
  напряжение в «горячем» пути — всегда коды, mV только для отладки (vbat_to_mv_*).
- Термокалибровка идёт отдельно (t_calibr в EE, tc в Option Bytes).
